NIDAR-SENSE VL53L5CX + USB CDC integration
===========================================

1. ST ULD API files are NOT modified.
   Existing:
       Drivers/BSP/Components/VL53L5CX_ULD_API/inc/*
       Drivers/BSP/Components/VL53L5CX_ULD_API/src/*

2. Add:
       platform.h -> Drivers/BSP/Components/VL53L5CX_ULD_API/inc/platform.h
       platform.c -> Drivers/BSP/Components/VL53L5CX_ULD_API/src/platform.c
       tof.h      -> Core/Inc/tof.h
       tof.c      -> Core/Src/tof.c
       serial.h   -> Core/Inc/serial.h
       serial.c   -> Core/Src/serial.c

3. WeAct STM32H743VIT6 V12 schematic choice:
       I2C1_SCL = PB8
       I2C1_SDA = PB9
       ToF GPIO1/INT = PB0 (free header GPIO, EXTI0 capable)
       USB FS DM = PA11
       USB FS DP = PA12

4. The supplied NIDAR .ioc currently has I2C1 on PB6/PB7. To follow the
   WeAct V12 schematic, change the I2C1 pin assignment in CubeMX to PB8/PB9.
   This is a pin configuration change, not a change to the ST ULD API.

5. Configure PB0 as GPIO EXTI rising edge and enable EXTI0. The generated
   stm32h7xx_it.c should contain the normal EXTI0 handler. Do not add ULD
   code to that generated file. The driver supplies HAL_GPIO_EXTI_Callback()
   from tof.c.

6. USB is already configured Device_Only on PA11/PA12. Add USB_DEVICE middleware
   with the CDC class in CubeMX. This generates usb_device.c/.h and
   usbd_cdc_if.c/.h. Keep those generated files generated; serial.c talks to
   the ST CDC class directly.

7. Call MX_USB_DEVICE_Init() from main.c in the generated USER CODE 2 area,
   after MX_USB_OTG_FS_PCD_Init(). Then call TOF_Init() and SERIAL_Init().

8. Runtime loop:
       while (1)
       {
           TOF_Process();
           SERIAL_Process();
           // time-critical application code can run independently
       }

9. ToF GPIO interrupt does NOT read I2C. It only sets a flag. The ULD's
   get_ranging_data() remains outside interrupt context because the supplied
   ST API/platform interface is synchronous.

10. SERIAL_Process() never waits for USB. It checks the CDC TxState and starts
    a packet only when the previous packet has completed.

11. The PC receives a binary 262-byte packet:
       [0]      0xA5
       [1]      0x5A
       [2]      protocol version = 1
       [3]      ToF stream/frame ID
       [4..131] 64 x int16 distance_mm, little-endian
       [132..195] 64 x uint8 target_status
       [196..259] 64 x uint8 target_count
       [260..261] CRC16-CCITT, little-endian

12. The critical code can consume:
       const TOF_Data_t *tof = TOF_GetData();
       tof->distance_mm[zone]
       tof->target_status[zone]
       tof->target_count[zone]
   No serial call is required for the control algorithm.
